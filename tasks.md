## Start here if you are picking this up

```bash
pnpm install
```

```bash
pnpm -r typecheck
```

```bash
pnpm --filter @prompt-enhancer/prompts test
```

Then press <kbd>F5</kbd> ("Run Extension") and enhance a selection with
<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>E</kbd>.

Things worth knowing before you write any code:

- **Prompt text goes in exactly one file.** `packages/prompts/templates/enhance.v1.md`. Do not
  add prompt strings to TypeScript, and do not create a second template server-side — that is
  the drift the design review removed (§5, D3).
- **Contributions land with their implementation.** Don't declare a command or participant in
  `package.json` before the code that handles it exists.
- **The document is never modified on failure** (§9.1). This is the rule most likely to be broken
  by accident in Phase 2.
- **Never log or message an API key.** All logging goes through `extension/src/log.ts`, which
  redacts at the boundary (§9.3).
- Two commits exist: `59d2899` is the original draft TDD (historical), `be9ab11` is the reviewed
  TDD plus Phase 1.

## Phase 2 — BYOK end to end ⬅ next

First genuinely usable version. No backend involved.

- [ ] `extension/src/services/SecretService.ts` wrapping `context.secrets`
      - key `promptEnhancer.geminiApiKey`; read per call, never cached in a module variable
      - must never touch `workspace.configuration` or workspace state (§8 Flow C)
- [ ] Commands `promptEnhancer.setApiKey` / `clearApiKey`, and **add them to
      `extension/package.json` contributions in this phase**
      - `showInputBox` with `password: true`
      - on set, validate with one minimal `models.list` call and report the result; do not store
        an invalid key silently
- [ ] `extension/src/services/GeminiDirect.ts` — direct `generateContent` call using
      `MODEL_ID` from the prompts package, global `fetch`, `AbortController` support
- [ ] Rewrite `enhanceSelection` to replace the Phase 1 preview with the real call:
      - [ ] `withProgress` at `ProgressLocation.Notification`, cancellable; cancel aborts the
            request and leaves the document untouched
      - [ ] **Document-version guard** — capture `document.version` and the range up front; if the
            document changed while the request was in flight, do not replace, open the result in a
            preview document instead (§8 Flow A.6)
      - [ ] Single `editBuilder.replace()` on the original range so it is one undo step
      - [ ] No key present → error message with a "Set API Key" action
- [ ] Error mapping and UX rules from §9: one `showErrorMessage`, "Open Output" action, 30 s
      timeout with retry, offline reported as offline
- [ ] Tests: error mapping, key redaction, cap enforcement

**Acceptance:** with a Gemini key set, selecting rough text and pressing the keybinding replaces it
with a structured prompt in one undo step; every failure path leaves the buffer exactly as it was.

## Phase 5 — Proxy client

- [ ] `extension/src/services/ProxyClient.ts`
      - [ ] Anonymous sign-in via Identity Toolkit `accounts:signUp` using the Firebase **Web API
            key** (public by design, safe to ship)
      - [ ] Refresh token stored in `SecretStorage`; ID tokens refreshed on demand, held in memory
            only
      - [ ] ID token sent as `Authorization: Bearer` so `request.auth.uid` populates
      - [ ] Payload wrapped in `{ "data": { ... } }`; response read from `result`
- [ ] `extension/src/services/ApiClient.ts` routing: key present → `GeminiDirect`, otherwise
      `ProxyClient`, otherwise prompt the user to set a key
- [ ] `resource-exhausted` UX: "Daily free limit reached — add your own API key to continue" with
      a "Set API Key" action
- [ ] Setting where a user can opt out of the proxy entirely (privacy — some users cannot send
      code off-machine)

**Acceptance:** a fresh install with no key enhances successfully via the proxy, and hitting the
daily cap surfaces the quota message with a working action button.
